# v1.0.9 — 番茄章节上传工具

## 本版：启动时间减半、单章上传快 4 秒

### 启动：806ms → 370ms（-54%）

用 `CU_BOOT=1` 分段量出来的：

| 阶段 | 优化前 | 优化后 |
|---|---|---|
| QApplication 初始化 | 80ms | 65ms |
| MainWindow 构造 | **640ms** | **145ms** |
| ├ 建控件 | 46ms | 46ms |
| └ QSS 应用（polish） | **480ms** | **2ms** |
| show + 首帧 | 90ms | 75ms |

**根因**：QSS 里那条

```css
QPlainTextEdit#log { font-family:"Consolas","Courier New"; ... }
```

Qt 把 `"Consolas","Courier New"` 当成**一个**字体名去查（带引号和逗号），查不到就回退——
而且**每个控件 polish 时都要重做一次**。78 个控件累起来就是 460ms。
一条声明拖掉了整个启动时间的一半。

修法：`font-family` 从 QSS 里删掉，日志控件在代码里 `setFont(QFont("Consolas"))` 设一次。

同类问题一并清掉：`QLabel { font-size:13px }`、`QPushButton { font-size:13px }`、
输入框组、QCheckBox 的字号声明都删了，改成 `app.setFont(13px)` 全局设一次 ——
QSS 里只保留真正有差异的字号（标题 19px、副标题 12px、提示 11px 等）。

### 运行时间：单章 11s → 7s

| 环节 | 优化前 | 优化后 |
|---|---|---|
| 全面检测轮询 | 3000ms/次 | 1500ms/次（提早发现完成） |
| 发布日期时间设置 | ~4.0s | ~2.0s |
| 发布回执轮询 | 2000ms | 1200ms |

`setPublish` 里各段等待按实测收紧（打开面板 450→320、点格 420→350、确定 380→260、
收浮层 380→260、点完等重渲染 700→250），校验逻辑不变（仍读 React `props.value`）。

### 其他

- `CMAKE_BUILD_TYPE` 未指定时**默认 Release**：无优化版启动要多花一倍时间。
  在 Qt Creator 里跑请用 Release 配置（`Desktop_Qt_6_8_3_MinGW_64_bit_Debug` 是 Debug 版）。
- 新增 `CU_BOOT=1`：把分段启动耗时写进 `%TEMP%\fqboot.txt` 后自动退出，方便以后回归对比。

# v1.0.8 — 番茄章节上传工具

## 本版修的两个关键问题

### 1. 时间选完没点「确定」，提交的还是旧时间

Arco 的 TimePicker 带 footer（「此刻」「确定」），**只点小时/分钟只是改面板里的临时高亮，
不点「确定」就不会写进组件状态**。v1.0.7 的确定按钮是在 `.arco-timepicker` 里找的，
按钮实际在浮层根的 `.arco-timepicker-footer` 里 → `querySelectorAll('button')` 找不到 →
静默跳过 → 输入框显示对了、提交还是弹窗默认值（19:05）。

| 项 | 旧 | 现在 |
|---|---|---|
| 点确定 | 只在 `.arco-timepicker` 内找 button | `confirmPicker()`：从 `.arco-trigger` 找 → footer 内最后一个按钮 → 文字匹配「确定」三级兜底 |
| 校验 | 回读 `input.value` + 重开面板看高亮 | 直接读 React 组件 `props.value`（真正的受控状态） |

> 踩坑记录：**打开面板会让 Arco 把 `input.value` 回写成 state**，所以「重开面板看高亮」这条
> 校验本身也会假通过（我方实测：手写显示值 20:15，重开面板后高亮就变 20:15）。
> 唯一可信的判据是 React `props.value`。

真机铁证（把值设成默认绝不可能出现的 19:37）：

```
before state = 20:15   →  pickTimeByPanel('19:37') = true  →  state = 19:37
```

### 2. 点「启动浏览器」像卡住

CDP 探测走 `QNetworkAccessManager`，默认继承 Windows 系统代理。本机装了本地代理
（127.0.0.1:11934）时，连 `127.0.0.1:9333` 的请求会被丢给代理，挂到超时才回。

- `CdpClient` 构造里 `m_net.setProxy(QNetworkProxy::NoProxy)` —— CDP 只连本机，永不走代理。
- 顺带加 `Page.bringToFront()`：浏览器在后台时 Chromium 会把 `setTimeout` 深度节流
  （最长 1 分钟一次），设定时这种「点面板 + 等渲染」的长流程会被拖到 JS 超时。
  进发布设置前先把标签提到前台。

### 真机验证（第 33 章，停在发布设置不发布）

```
[15:30:52] 已进入发布设置
[15:30:56] 发布设置：AI=否 / 定时发布=开 / 日期=2026-11-06 / 时间=19:00
[15:30:56] 定时：2026-11-06 19:00（读回校验通过）
```

4 秒完成（比 v1.0.7 更快，因为不再反复开关面板核对）。`tools/test.html` **52 项全过**
（新增 R1 点中 footer 的确定、R2 校验读 React state 而非显示值）。

现象：日志写 `定时：2026-11-06 19:00（读回校验通过）`，后台实际却是 **2026-11-05 19:05**

| 打开方式踩坑 | `focus()` + `mousedown` 会把刚打开的面板又关掉（开/关相互抵消） | 只用 `input.click()`；重开面板前先判 `isOpen` |
| AI/开关查找慢且脆 | 按全文文案扫 + 逐层爬父节点 | 在 `.arco-modal-wrapper` 里点 `.arco-radio`（文案「否」）/ `.arco-switch`（看 `arco-switch-checked`），保留文案兜底 |

# v1.0.5 — 番茄章节上传工具

## 本版修的关键问题：填进去的章号/标题会「消失」

报告的现象是点完【下一步】弹红条 **「标题至少输入5个字，章节序号只支持阿拉伯数字」**，
而页面上「第 __ 章」和标题框都是空的 —— 日志却显示「章号=27 标题=…」。

根因有两层：

| 层 | 说明 | 现在 |
|---|---|---|
| 写得太早 | 番茄编辑页是 SPA：`/publish/` 先渲染一版骨架，再整体换成真编辑器。旧版连上新标签就立刻写值，值写进的是**马上被替换掉的那批元素**，所以「写的时候回读是对的，过一会儿页面上什么都没有」 | 新增 `S_Ready` 阶段：章号框 + 标题框 + 正文编辑器都在，且**连续 500ms 指向同一批元素**才动手写（`__fq.editStable()`） |
| 没核对 | 旧版只在写入的瞬间回读一次 | 拆成 `S_Fill`（只写章号/标题）→ `S_Body`（写正文）→ `S_Check`（**650ms 后重新回读页面**核对章号/标题/字数），不符就重写，最多 5 次；仍不符则带着回读值报错 |

另外：

- **章号框定位改成按结构**：番茄的章号 input **没有 placeholder**（`.serial-editor-title-left input`），旧版靠「父节点文本里有第…章」猜，页面结构一变就抓瞎。现在优先用结构，标题框的 `placeholder="请输入标题"` 作兜底锚点。
- **标题格式可配**：新增勾选「标题带章号（27归队）」，默认勾上——与这本书后台已有的「第26章 26骸骨」写法一致；取消勾选则用纯标题「归队」。
- **番茄校验提示直接报出来**：等发布设置时若出现「正文至少输入1000字」「标题至少输入5个字」这类红条，立即存草稿并中断，不再干等到超时。

[14:13:44]   编辑页已就绪

# v1.0.0 — 番茄章节上传工具

把「每章一个 txt」批量传上番茄小说网作家后台：自动建章、自动纠错、自动全面检测、按规则定时发布。

## 下载

| 文件 | 说明 |
|---|---|
| `FanqieUploader-v1.0.1-win64-portable.zip` | **推荐**，解压即用，已带 Qt 6.8 运行库 |
| `FanqieUploader.exe` | 单文件（需自备 Qt 运行库，一般用上面那个） |

需要 Windows 10/11 + Edge 或 Chrome。

## 首次使用

1. 解压后双击 `FanqieUploader.exe`
2. 点「启动浏览器」→ 在弹出的浏览器里**登录番茄作家账号**（登录态会保留）
3. 进到目标书的「章节管理」页 → 点工具里的「刷新」读书名与分卷
4. 选章节文件夹、设首章日期 → 「开始上传」

## 主要能力

- **按文本驱动页面**：不依赖随机化的 class 名，兼容后台改版
- **完整流程**：章节管理 → 选卷 → 新建章节 → 章号/标题/正文 → 下一步 → 错别字弹窗取消 → 智能纠错「替换全部」→ 全面检测 → 发布设置（AI 否 + 定时）→ 确认发布
- **自动循环**：错别字弹窗可能反复出现，自动重复「取消 → 替换全部 → 下一步」直到进入全面检测
- **定时排期**：每天 3 章，19:00 / 19:05 / 19:10，第 4 章自动顺延次日
- **异常兜底**：风险提示 / 发布失败 / 定时设置失败 → **先存草稿**再弹警告并中断，不让稿子白填
- **定时校验**：日期时间写不进去就**不点确认发布**，避免变成立即发布
- **页面勘察**：一键打印当前页所有可见按钮与输入框，便于排障
