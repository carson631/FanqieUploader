# v1.0.3 — 番茄章节上传工具

## 本版改了什么

| 改动 | 说明 |
|---|---|
| 启动日志打版本+构建时间 | 第一行固定输出 `FanqieUploader v1.0.3　构建 2026-11-05 13:36`，以后一眼能看出跑的是不是新编译的版本（上一版就是因为旧进程还开着，点上传用的还是老代码） |
| 接管新标签更宽容 | 新标签刚建出来时 URL 可能是空或先落到别的路由，等 2.5 秒还没有 `/publish/` 精确匹配时，就先接住那个新开的番茄页，再由 `stage()` 判定是不是编辑页 |
| 版本号 | 1.0.2 → 1.0.3 |

## 真机验证

`tools/followtest/`（直接调 `CdpClient`，在真实番茄后台上跑）：

```
点【新建章节】…
newChapter 返回：[{"ok":true,"text":"新建章节"}]
[cdp] 目标页：https://fanqienovel.com/main/writer/<书id>/publish/?enter_from=newchapter
followNewTarget 成功(825ms)，新标签 A3A0CF3A…
stage: editor=1 bodyEditor=1 manage=0 publish=0
```

注意新标签的 URL 是 `/publish/?enter_from=newchapter`（没有章号），所以判定用 `包含 /publish/`，不能去解析章 id。

# v1.0.2 — 番茄章节上传工具

修掉「新建章节后找不到编辑页」——番茄是把编辑页开在**新标签**里，老版本一直在旧标签上找。

## 本版修复

| 现象 | 原因 | 现在 |
|---|---|---|
| `✗ 新建章编辑页没出来（标题框找不到）`，但浏览器里编辑页明明已经打开 | 点【新建章节】后番茄 `window.open` 开了**新标签**，旧标签还停在章节列表；调试连接一直盯着旧标签，`stage().editor` 永远是 false | 点之前先记下现有标签 id，点完用 `followNewTarget()` 接住新出现的 `/publish/` 标签并切换连接 |
| 跑 150 章会攒出 150 个编辑标签 | 每章关一次都没有 | 每章提交完 `closeTarget()` 关掉本章的编辑标签，再切回章节管理页 |
| 编辑页顶部也有「书名 + 第二卷：xxx」，被误判成章节管理页 | `stage().manage` 只看「有分卷下拉」 | 加条件：**存在标题输入框或发布设置时不算管理页**（`manage = (新建章节\|分卷) && !编辑页`） |
| 从编辑页起跑时直接退出 | 老逻辑只提示「请手动回到章节管理页」 | 先自动切回章节管理标签（不关任何标签，避免丢手写内容），切不过去才退出 |

## 新增测试

- `tools/cdp_tabtest/`：直接调 `CdpClient` 的 C++ 冒烟测试（`window.open` 新标签 → `followNewTarget` 接住 → 在新标签里执行 JS → `closeTarget` 关掉），6 项断言全过
- `tools/test.html` 44 → **45 项**：新增「编辑页不能被当成章节管理页」

## 验证

- 真机确认：点【新建章节】后 `/json/list` 出现 `…/main/writer/<书>/publish/<章>?enter_from=newchapter` 的新标签，旧标签仍停在 `chapter-manage` → 正是老版卡住的原因
- 冒烟测试：`followNewTarget` 正确返回新标签 id、连接切过去、JS 在新标签里可执行、`/json/close` 能把标签关掉

# v1.0.1 — 番茄章节上传工具

修掉「书名/分卷读错」，并新增「只传某一段章节」。

## 本版修复

| 问题 | 原因 | 现在 |
|---|---|---|
| 读到 3 本书：`佣兵2：铁誓之约 / 章节管理 / 新建章节` | 老逻辑按「字号 ≥13 且祖先里有『章节管理』」筛，按钮文案本身也满足 | 优先读书卡语义类名（`.home-book-item` / `.completion-book-item`），并有固定文案黑名单 + `第N章` 排除 |
| 读到 3 个分卷，还带「审核状态 全部 搜索章节…」 | 只要求「整段文本里出现一次 第X卷」，外层容器也命中 | 收紧为「`第X卷[: 卷名]`、卷名不含空格、≤16 字」，容器一律不算 |
| 分卷顺序是「第二卷、第一卷」 | 后台按新版在前返回 | 按卷号升序排列：第一卷、第二卷 |
| 刷新分卷有时读不到 | 下拉展开状态不确定，再点一次反而收起 | 读之前先点开、读完再收起，界面状态确定 |

## 本版新增

- **章节范围**：`③ 章节源与排期` 里新增「第 X 章 至 第 Y 章」，只上传目录里这一段
  - 默认全选（最小~最大章号），改完自动重算右侧表格与定时排期
  - 起止写反自动纠正；范围为空会提示，不会误发
  - 范围随目录与设置一起记住

## 验证

- `tools/test.html`：**44 项断言全过**（新增 6 项：两种书卡的书名、章节预览行不当书名、容器文本不当卷名、展开态选卷）
- **真实后台复验**（用工具自己的登录 profile、无头 Edge + CDP）：
  - `__fq.books()` → `["佣兵2：铁誓之约","佣兵1：流亡之刃"]`
  - `__fq.volumes()` → `["第一卷：铁誓之约","第二卷：圣歌与暗金"]`

# v1.0.0 — 番茄章节上传工具

把「每章一个 txt」批量传上番茄小说网作家后台：自动建章、自动纠错、自动全面检测、按规则定时发布。

## 下载

| 文件 | 说明 |
|---|---|
| `FanqieUploader-v1.0.1-win64-portable.zip` | **推荐**，解压即用，已带 Qt 6.8 运行库 |
| `FanqieUploader.exe` | 单文件（需自备 Qt 运行库，一般用上面那个） |

需要 Windows 10/11 + Edge 或 Chrome。

## 首次使用

1. 解压后双击 `FanqieUploader.exe`
2. 点「启动浏览器」→ 在弹出的浏览器里**登录番茄作家账号**（登录态会保留）
3. 进到目标书的「章节管理」页 → 点工具里的「刷新」读书名与分卷
4. 选章节文件夹、设首章日期 → 「开始上传」

## 主要能力

- **按文本驱动页面**：不依赖随机化的 class 名，兼容后台改版
- **完整流程**：章节管理 → 选卷 → 新建章节 → 章号/标题/正文 → 下一步 → 错别字弹窗取消 → 智能纠错「替换全部」→ 全面检测 → 发布设置（AI 否 + 定时）→ 确认发布
- **自动循环**：错别字弹窗可能反复出现，自动重复「取消 → 替换全部 → 下一步」直到进入全面检测
- **定时排期**：每天 3 章，19:00 / 19:05 / 19:10，第 4 章自动顺延次日
- **异常兜底**：风险提示 / 发布失败 / 定时设置失败 → **先存草稿**再弹警告并中断，不让稿子白填
- **定时校验**：日期时间写不进去就**不点确认发布**，避免变成立即发布
- **页面勘察**：一键打印当前页所有可见按钮与输入框，便于排障

## 验证情况

- `tools/test.html` 用真实 Edge（headless）跑 **37 项断言**，覆盖：
  - 编辑页右侧「暂无错别字」不被误判为弹窗
  - 书籍列表页不被误判为章节管理页
  - 错别字弹窗 → 取消；纠错页 → 替换全部 + 下一步
  - 检测弹窗 → 全面检测；风险数字解析 → 中断
  - 发布设置：勾「否」、开定时、写日期时间并回读校验
  - 存草稿、选卷（不会点到外层聚合容器）、填章号/标题、正文写入字数
- 真实 150 章数据：排期 11-06 19:00 → 12-25 19:10，跨 50 天，与规则一致
- 便携包解压到纯净 PATH 环境可直接启动（不依赖已安装的 Qt）

## 已知边界

- 页面结构大改（按钮文案变化）需要更新 `js/site.js`；届时用「勘察页面」把日志发出来即可定位
- 上传期间请勿在同一浏览器页面手动操作，也不要开第二个工具实例
- 正文写入会在字数不符时自动重试另一种方式；若编辑器仍拒收会存草稿并中断
- 不处理"新建卷"：请先在后台把目标卷建好并在工具里选中
